# PC-TFN: Physics-Calibrated Trajectory-Forecasting Network for Climate-Resilient Data Center Risk Classification

This repository contains the source code for the study *"Physics-Calibrated Trajectory Forecasting for Climate-Resilient Data Center Operations: A Calibrated Hybrid Architecture"* (Massaoudi). It is released for reproducibility and contains **only source code**: no pre-generated tables, figures, trained checkpoints, or raw/processed data.

The public URL remains [https://github.com/Mmassaoudi-cell/PC-TCN](https://github.com/Mmassaoudi-cell/PC-TCN); the proposed model in this release is **PC-TFN**.

## Overview

Data centers need proactive (multi-hour-ahead) classification of weather- and grid-driven operational hazard severity, not just reactive threshold alarms. This study builds a chronological, weather-driven digital twin of four development data-center sites (San Francisco, Phoenix, Chicago, Dallas) plus one zero-shot external site (London), using public ERA5-Land reanalysis weather and a fully disclosed, deterministic facility simulator. Each sample is labeled with the most severe hazard class (normal / advisory / warning / critical) occurring in the following 6 hours.

An oracle study on the validation split shows that a 0.80--0.81 full-coverage macro-F1 plateau is an information ceiling of the six-hour, history-only task: handing a regressor the true next six hours of temperature, humidity, and dew point lifts validation macro-F1 to 0.922, whereas the remaining meteorological variables contribute nothing. The proposed model, **PC-TFN (Physics-Calibrated Trajectory-Forecasting Network)**, therefore makes that latent thermal trajectory an explicit, supervised intermediate:

1. a depthwise-separable multi-scale dilated encoder (dilations 1-2-4-8) with explicit velocity channels;
2. last / mean / max / attention multi-head pooling;
3. a residual thermal-forecast head for \(t{+}1,\ldots,t{+}6\) temperature, humidity, and dew point;
4. a physics-risk surrogate mapping that forecast onto the six future risk scores;
5. a softmax expert gate fusing the temporal, physics-state, and forecast-risk experts.

The classifier is trained with class-weighted focal loss plus two auxiliary Huber terms, then calibrated with validation-only temperature scaling and entropy-based abstention. Metrics are reported at full coverage and at the protocol's 10% deferral / 91% coverage operating point, with per-class coverage disclosed.

## What Is Included

Source only: the data/simulation pipeline, the proposed PC-TFN model and every baseline architecture, auxiliary-target construction, training/calibration/evaluation utilities, the reconstruction of the prior rule-based method, and the experiment-orchestration scripts. It does not include generated weather/simulated data, result tables or figures, or trained model weights. Every artifact can be regenerated by running the scripts.

## Repository Structure

- `src/resilient_dc/data_pipeline.py`: fetches ERA5-Land hourly weather (Open-Meteo historical archive), runs the disclosed facility simulator, assigns chronological splits, and writes processed per-site datasets.
- `src/resilient_dc/aux_targets.py`: materialises the training-split-only thermal-trajectory and future-risk auxiliary targets used by PC-TFN. These are never model inputs and are never computed from the frozen test or external splits at inference time.
- `src/resilient_dc/modeling.py`: feature-bundle construction and standardization (train-split statistics only), `PhysicsTrajectoryNet` (PC-TFN) together with `SqueezeExcite`, `SeparableBlock`, `MultiPool`, and `ExpertGate`, the multi-task trainer `train_pc_tfn`, every other architecture used in the study, class-weighted focal loss, temperature scaling, entropy abstention, and evaluation metrics including selective (coverage-conditioned) scores.
- `src/resilient_dc/benchmarks.py`: classical, boosting, and generic-deep benchmark suite, each trained on the training split with any selection decided on validation only.
- `SOURCE_METHOD_REPRODUCTION/`: reconstruction of the threshold-based prior proposal (location-specific heat-wave threshold, advisory/warning/critical escalation, cooling-headroom and grid-stability thresholds).
- `scripts/run_candidate_screening.py`: 3-seed smoke test and validation screening of hybrid candidates.
- `scripts/tune_top_candidates.py` / `scripts/tune_benchmarks.py`: validation-only Optuna search.
- `scripts/run_final_evaluation.py`: trains the frozen PC-TFN configuration, every benchmark, and the source-method reconstruction; evaluates once on the frozen test split and once on untouched London.
- `scripts/run_ablation.py`: one-mechanism-at-a-time ablation of the frozen PC-TFN (thermal head, physics surrogate, expert gate, multi-head pooling, focal loss).
- `scripts/run_robustness.py`: low-data, feature-noise, and missingness curves for the frozen PC-TFN.
- `scripts/add_selective_metrics.py`: backfills 90%-coverage metrics from frozen checkpoints (no retraining).
- `scripts/compute_statistics.py`: paired Wilcoxon tests with Holm-Bonferroni correction.
- `FINAL_MODEL_CONFIG.yaml`: frozen PC-TFN architecture, hyperparameters, splits, and training/calibration protocol.
- `requirements.txt`: pinned Python package versions.

## Method Summary

### Data and Labeling

Each of the five sites is driven by its own historical hourly ERA5-Land weather series through a disclosed deterministic simulator. The instantaneous risk score is discretized into four ordinal classes (cut-points 0.08 / 0.36 / 0.72); the prediction target at each hour is the most severe class over the next 6 hours. Splits are chronological (train 2018--2021, validation 2022, test 2023--2024) across the four development sites, with London held out entirely as a zero-shot external site. All preprocessing statistics are fit on the training split only.

### Model Architecture (PC-TFN)

The 15-dimensional 24-hour trajectory is concatenated with first differences and encoded by pre-norm depthwise-separable dilated residual blocks (dilations 1, 2, 4, 8; receptive field 31 > 24). A multi-head read-out concatenates the last step, mean, max, and a learned-query attention summary. The thermal head predicts a residual on a persistence anchor; the physics-risk surrogate maps the flattened forecast, the current physics state, and the temporal embedding onto six future log-risk scores. A softmax expert gate fuses the temporal representation, the encoded physics state, and an embedding of the forecast-risk summary. Frozen width \(C=40\) gives 58,949 parameters.

Ablated variants (used only after the configuration is frozen) turn off the thermal head, the surrogate, the expert gate (replaced by concatenation), multi-head pooling (replaced by mean pooling), or focal loss (replaced by weighted cross-entropy), one at a time.

### Training, Calibration, and Abstention

PC-TFN is trained with AdamW and a one-cycle schedule. The objective is class-weighted focal loss plus Huber loss on the thermal trajectory (\(\lambda=1\), \(\delta=1\)) and Huber loss on log1p future risk (\(\lambda=1\), \(\delta=0.1\)). Early stopping uses validation macro-F1 (patience 10, up to 40 epochs). After training, per-seed temperature scaling is fit on the validation split, and a per-seed entropy threshold is selected there for a 10% target deferral rate. Both are applied unchanged at test time. Auxiliary targets are training-split supervision only.

### Evaluation Protocol

Architecture and hyperparameter selection use only the training and validation splits. The frozen configuration is then trained and evaluated over 10 independent seeds on the untouched test split and the zero-shot London split. Ablation reuses the same 10 seeds; robustness and low-data experiments use 5 seeds. No step after freezing may feed back into architecture or hyperparameter choices.

## Reproducing the Experiments

All commands below are run from the repository root, with `src` on `PYTHONPATH`.

### 1. Build the weather-driven digital-twin dataset

```powershell
$env:PYTHONPATH = (Resolve-Path "src").Path
python src/resilient_dc/data_pipeline.py
```

This fetches ERA5-Land hourly weather for all five sites from the public Open-Meteo historical archive (2018-01-01 through 2024-12-31, UTC), writes a SHA-256 provenance record, runs the disclosed facility simulator, assigns the chronological per-site splits, and writes the processed per-site datasets and the sample-level split manifest.

### 2. Reconstruct and evaluate the prior rule-based method

```powershell
python SOURCE_METHOD_REPRODUCTION/run_reproduction.py --split validation
```

### 3. Screen candidate hybrid architectures

```powershell
python scripts/run_candidate_screening.py --stage smoke
python scripts/run_candidate_screening.py --stage screen
```

### 4. Validation-only hyperparameter tuning

```powershell
python scripts/tune_top_candidates.py --candidate both --trials 25 --top-k 5
python scripts/tune_benchmarks.py
```

`FINAL_MODEL_CONFIG.yaml` is then frozen by hand from the tuning outputs; no step after this point may be influenced by test-split results.

### 5. Frozen test and external (zero-shot) evaluation

```powershell
python scripts/run_final_evaluation.py --seeds 17 29 43 71 88 101 113 127 139 151
```

This trains the frozen PC-TFN configuration, every benchmark, and the source-method reconstruction on the frozen training split, and evaluates each once on the frozen test split and once on the untouched external (London) split.

### 6. Ablation of the frozen architecture

```powershell
python scripts/run_ablation.py --seeds 17 29 43 71 88 101 113 127 139 151
```

### 7. Robustness and low-data generalization

```powershell
python scripts/run_robustness.py --seeds 17 29 43 71 88
```

## Experimental Integrity Notes

- Architecture and hyperparameter selection use only the training and validation splits; the test and external splits are never used for tuning, early stopping, or calibration.
- `FINAL_MODEL_CONFIG.yaml` is frozen before any test-split evaluation.
- The external (London) site is used exclusively as a zero-shot test of generalization.
- All preprocessing statistics are fit on the training split only.
- Auxiliary thermal and risk targets are training-split supervision only; they are never model inputs.
- The facility simulator is a fully disclosed, deterministic research digital twin, not observed operator telemetry.
